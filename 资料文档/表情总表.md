## 五、提取流程(版本更新后复用)

1. 找总表：扫描 APK bundle 找含 EmojiConfig(TextAsset) 的 bundle，解析 protobuf 得全部表情路径/sprite/帧数。
2. 静态表情：定位含 Texture2D EmojiAtlas_1 的 bundle，解析 UIAtlas MonoBehaviour 的 sprite 数据。**sprite 结构 = name(4字节长度+内容+4对齐) + rect(4xint32=x,y,w,h) + rotation(1xint32, 0=正常/1=顺时针90度) + border(4xint32) + padding(4xint32=四边裁剪量)**。切图规则：rotation=0 时按 (x,y,w,h) 裁剪；**rotation=1 时先交换成 (x,y,h,w) 裁剪再 `rotate(-90)` 转正**（rotation=1 的 sprite 在贴图里实际占用 h×w 的横向区域，不交换会裁进相邻 sprite 的内容）。切完不要再按「最大连通域」裁剪（会把相邻素材带进来、把独立细节裁掉、还导致帧间错位闪烁），静态表情按 alpha 阈值 bbox 去透明边，帧动画直接用完整 rect 保证帧间对齐。坑①：rotation 字段最容易漏，漏了会整批表情横躺；坑②：不交换 w/h 会裁进隔壁表情素材。
3. 帧动画：同一图集按 前缀_0001.. 分组逐帧切图，按帧号排序合 GIF(画布取最大内容尺寸，帧左上对齐)。
4. 动态 Spine：按 Common/EmojiSpines/xxx 在 APK bundle 里扫描含该名字者，用 火影解包器.py 提取 json/atlas/png 再 render 成 GIF。
5. 渲染：python 火影解包器.py render <json> <atlas> <png> -o 输出.gif。**Spine 渲染两大坑**：①区域附件(region)的 UV 必须用 RegionAttachment.setRegion 的「直接区域坐标」——rotate(90°) 时 u2=x+h/v2=y+w、角点按 [BL,BR,TR,TL]=[(u2,v2),(u2,v),(u,v),(u,v2)] 排列；**绝不能**用 Mesh 的 updateUVs 公式(带 offset/orig 修正)去算 region 的 UV，否则旋转帧会采错贴图区域、出现「多火焰/糊成一团」。②offset/orig!=size 的修正只作用于**顶点位置**(updateOffset)，不作用于 UV。

## 六、关键脚本
- 脚本/火影解包器.py：KHFS 解密 + Spine 渲染 + CLI。
- 脚本/_parse_config4.py：解析 EmojiConfig protobuf 到 emoji_master3.txt。
- 脚本/_scan_all_sprites.py：解析图集全部 sprite name+rect 到 atlas_sprites.json。
- 脚本/_slice_final.py：静态表情切图(含连通域修正)。
- 脚本/_assemble_frame_gifs.py：帧动画合 GIF。
- 脚本/_scan_missing.py：扫描缺失 Spine 表情的 bundle 位置。
