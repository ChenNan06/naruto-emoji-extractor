# 表情提取器 · 使用说明(面向人类用户)

一键提取火影忍者手游表情的成品工具。游戏版本更新后，只需重新跑一次，就能把三类表情(静态 PNG + 帧动画 GIF + 动态 Spine GIF)全部导出。

## 零、点开即用(GUI / EXE, 推荐)

普通用户**不用装 Python、不用敲命令**，直接双击：

- 工具/表情提取器/表情提取器.exe(单文件，约 47 MB，双击即开图形界面)
- 或根目录的 一键提取表情.bat(需本机装了 Python + 依赖，双击等效)

打开后：① 选「bundle 目录」(游戏资源的 assets/bundle 或 com.tencent.KiHan/files/999/bundle)；② 选「输出目录」(表情存到哪)；③ 点「开始提取」。日志实时滚动显示进度，完成后到输出目录取货。可勾选「跳过动态 Spine」只提取静态/帧动画(更快)。

> 想改默认行为(如自定义导出路径、是否含 Spine)都在 GUI 界面上直接选，不用改代码。

## 一、环境准备(一次性，仅命令行方式需要)

1. 安装 Python 3.8+。
2. 安装依赖：

```
pip install pillow numpy unitypy
```

## 二、三个命令

| 命令 | 作用 |
|------|------|
| extract | 一键提取全部表情(静态 + 帧动画 + 动态 Spine) |
| list | 只解析并打印表情总表(不导出) |
| render | 渲染单个 Spine 表情 |

### 1. 一键提取(最常用)

```
python 表情提取器.py extract <bundle目录> -o <输出目录>
```

示例：

```
python 表情提取器.py extract "E:/naruto/火影忍者_1.78.78.8/assets/bundle" -o "E:/naruto/表情导出"
```

程序会自动完成：
1. 扫描 bundle 目录，定位「EmojiConfig(表情总表)」和「EmojiAtlas_1(图集)」；
2. 从图集切出静态表情(PNG)和帧动画(GIF)；
3. 扫描并渲染动态 Spine 表情(GIF)。

> 首次扫描 1.4 万个 bundle 约 1~2 分钟。只想做静态/帧动画、跳过慢的动态部分，加 --no-spine：

```
python 表情提取器.py extract <bundle目录> --no-spine
```

### 2. 只看表情总表

```
python 表情提取器.py list <bundle目录>
```

### 3. 渲染单个表情

```
python 表情提取器.py render <xxx.json> <xxx.atlas> <xxx.png> -o 输出.gif
```

## 三、输出结构

```
输出目录/
├── 表情总表.txt         # 全部表情的中文名/类型/素材路径(人读)
├── 静态表情/
│   └── <中文>_<拼音>.png
├── 帧动画/
│   └── <中文>_<前缀>.gif
└── 动态表情/
    ├── <中文>__<资产名>.gif
    ├── <资产名>.json / .atlas / .png   # 渲染源文件
```

## 四、版本更新后怎么复用

游戏发新版后，把新 APK 解包得到新的 assets/bundle 目录(或下载目录 com.tencent.KiHan/files/999/bundle)，然后直接：

```
python 表情提取器.py extract <新bundle目录> -o <新输出目录>
```

不需要改任何代码——程序会自动重新定位 EmojiConfig / EmojiAtlas / Spine bundle(它们的数字 ID 每次都会变)。

## 五、程序内部已解决的坑(接手维护者必读)

1. 图集 sprite 带 rotation 字段：0=正常，1=在贴图里顺时针转了 90°。切图时 1 要先交换宽高 (x,y,h,w) 再 rotate(-90) 转正，否则会裁进相邻表情。
2. 静态/帧动画不能按「最大连通域」裁剪：会带入相邻素材、裁掉独立细节、导致帧间闪烁。静态按 alpha 阈值去透明边，帧动画直接用完整 rect。
3. Spine region 与 mesh 的 UV 是两套公式：region 用 setRegion 的直接区域坐标(90° 时 u2=x+h/v2=y+w、角点排列)，mesh 才用带 offset/orig 修正的 updateUVs 公式。弄混会导致旋转帧采错贴图、出现「多火焰/糊成一团」。
4. offset/orig≠size 的白边裁剪修正只作用于顶点位置，不作用于 UV。
5. **region/mesh 附件的纹理必须用 `path` 字段(不是附件名)查图集**。spine-core.js 是 `path = map.path || name`。有个别附件的 path≠附件名(驰骋表情的「辫子/绳索套」region 附件 path=`bianzi_001`、附件名=`bianzi`)，查错会采到完整辫子贴图、导致绳套顶部「有一帧卡住不动」的违和感。
6. **垂钓表情鱼线过长**：`bq_2026_diaoyu`(垂钓)的鱼线 mesh 从鱼竿一直垂到底，让画面被拉得又细又长。程序对资产名含 `diaoyu`/`chuidiao` 的 GIF 做专用后处理 `crop_fishing_line`：按「每行内容宽度」区分密集主体(角色/鱼竿)与细线(鱼线)，把底部细线裁掉，只留角色+鱼竿。

## 六、已知限制

- 静态表情里的「搓/对」等旧版 sprite 不在当前 EmojiConfig 里，程序只导出配置里引用到的，不会导出这些遗留素材。
- 若某个表情版本更新后资产名变了，动态表情会用资产名兜底命名，中文名映射可能缺。
