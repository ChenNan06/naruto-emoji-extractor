# 常见问题（踩坑实录）

## 一、为什么普通的 AssetStudio 打不开火影的包，魔改的却可以？

### 结论一句话
**因为包不是标准 UnityFS。** 腾讯把容器头部的魔数改了名、又把「目录表」单独加密了；
普通 AssetStudio 一看到不是 `UnityFS` 就直接判成"不是 AssetBundle"，连解析都不进入。
魔改版只做了一件事：**在读取容器的那一层加了一个解密钩子**，把文件还原成标准 `UnityFS`
再交给原版逻辑 —— **解压、纹理、Sprite、网格这些代码一行都没改**。

### 具体差在哪

| 层 | 标准 UnityFS | 火影的包 |
|---|---|---|
| 文件头魔数 | `UnityFS\0` | **`UnityKH1FS` / `UnityKHFS` / `UnityKHNFS`**（三种，靠版本号区分） |
| 头版本 | 6 / 7 / 8 | 8（和标准一样，但后面接的字段是自定义的） |
| 目录表（BlocksInfo） | 明文 + 明文长度 | **加密**（自定义流密码，不是 LZ4/LZMA/zlib/brotli 任何一种） |
| 资源数据块 | LZ4 分块 | **和标准一模一样**：普通 LZ4，128KB 一块，**完全没加密** |

所以本质是「**壳换了个名字 + 目录表上锁**」，**数据本体是明文**。这就是为什么只要把目录表解开，
后面全部走原版流程就能读出来。

### 魔改版是怎么做到的（反编译 `AssetStudio.dll` 得到的结构）

DLL 里能看到这些新增符号，说明它把解密做成了**可插拔的解密器**：

```
ProcessBundle / CanBeDecrypted / CanBeDecrypted1 / CreateDecryptor
DecryptData / DecryptSpan / DecryptVersion / Decrypt
SingleByteXorLoader / XorStream / _xorKey
<FairGuard2Loader>…__CustomRc4 / <FairguardLoader>…__CustomCrc32
```

流程就是：

```
读文件 → 看头 4~11 字节魔数 → 命中解密器？
        ├─ 是 → 解密 BlocksInfo → 还原成标准 UnityFS 字节流 → 交给原版 AssetBundleFile
        └─ 否 → 原版逻辑（报错退出）
```

它内置的密钥就在 `AssetStudio.dll` 里（偏移 `550344` 和 `558448`），
和本仓库 `脚本/火影解包器.py` 里用的是同一对：

```
hAi5luE8FlyblDdCTQC9uxnj3rkNwd1swrKI7Mx1aDFEe2B5h…
X@85Pq!6v$lCt7UYsihH3!cPb1P71bo4lX59FXqY!VO$YiYsu!Keu3aVZwi5on5l
```

### 顺带说明
魔改版**只加了容器解密**，没有加 NGUI 图集解析（DLL 里 `mSprites` / `UISpriteData` / `pixelSize`
全是 0 命中）。所以它能把 `EmojiAtlas_1` 整张 2048×2048 导成一张 PNG，
但**不会**给你切成一个个表情 —— 切图是本仓库 `表情提取器.py` 干的活。

## 二、怎么拿到 MuMu 模拟器里面的文件？

三条路，按可靠性排序：

### 路线 A：离线直读 VDI（推荐，不用开模拟器、不占 CPU、零打扰）

MuMu 的虚拟磁盘就是一个标准 **VirtualBox VDI**：

```
E:\MuMuPlayer\vms\MuMuPlayer-15.0-0\data.vdi
```

结构（自己解析，不需要 VBoxManage）：

| 偏移 | 内容 | 本次实测值 |
|---|---|---|
| `0x40` | VDI 魔数 | `0xBEDA107F` |
| `0x154` | 块索引表偏移（512 字节为单位） | `0x154` → 512 |
| `0x158` | 数据区起始（字节） | `3815936` |
| `0x170` | 虚拟盘容量 | 931.5 GiB |
| `0x178` | 块大小 | **1 MiB** |

- 块索引表里每 4 字节是一个 **1MiB 块号**（不是 512 字节扇区号！这点最容易搞错，
  搞错就会解出一堆长度正确但全是 0 的文件）。
- 按块号拼出虚拟盘以后，开头是 MBR，分区 3（offset `78643200`）就是 Android 的 `/data`（ext4，**没开 FBE**）。
- ext4 里 ext4 根目录**就是** Android 的 `/data`，所以：

```
Android 路径  /sdcard/Android/data/com.tencent.KiHan/files
镜像内路径    /media/0/Android/data/com.tencent.KiHan/files
```

> 注意 `/sdcard` 是 `/data/media/0` 的软链，在 ext4 里没有这个目录，必须换算成 `/media/0`。

实测：**64,691 文件 / 19.4 GB / 93.2 秒 / 213 MiB/s / 0 错误**，与手工复制的副本逐字节一致（关键文件 MD5 全对）。

脚本：`脚本/提取MuMu磁盘文件.py`（本次工作区里的版本叫 `02_vdi_extract.py`，功能一样）

### 路线 B：adb 直连

```bash
adb connect 127.0.0.1:16384     # MuMu 默认端口
adb root                        # MuMu 自带 root，成功返回 uid=0(root)
adb shell ls /sdcard/Android/data/com.tencent.KiHan/files
adb pull /sdcard/Android/data/com.tencent.KiHan/files/999/bundle D:\kihan\bundle
```

适合只想拿几个文件的场合；整目录 pull 比 VDI 慢很多。

### 路线 C：MuMu 共享文件夹（最笨但最稳）

MuMu 设置里有「共享文件夹」，映射到 `E:\Documents\MuMu共享文件夹\`，
在模拟器里往这儿复制一份，Windows 侧直接能看。**本次最早就是靠这个起手的**，
但每次都要手动复制 20GB，所以后来改成了路线 A。

## 三、这套方法通用吗？

分三层看：

| 东西 | 通用性 |
|---|---|
| **VDI 离线读取** | ✅ **完全通用**。任何 VirtualBox VDI（MuMu / 雷电 4 / Genymotion…）都能用，只要按上表解析头 + 块表。 |
| **KHFS 解密** | ❌ **只对火影**。魔数、密钥、流密码都是这个游戏自己魔改的 `lib/arm64-v8a/libunity.so` 里写的，换游戏就换一套（甚至没有）。 |
| **"只加密目录表、数据块明文"这个套路** | ⚠️ **常见但不是必然**。腾讯系不少 Unity 手游是这么干的（改魔数 + 加密 BlocksInfo，数据块保留标准 LZ4），遇到新的包先按这个假设试，能省一大半力气。 |
| **NGUI 图集 + rotation 字段 + 三类表情结构** | ⚠️ **半通用**。NGUI 图集本身通用；但"第 5 个 int 是旋转标记"是这套自研 UIAtlas 的分支实现，别的项目可能没有。 |
| **判断思路** | ✅ **完全通用**：① 先确认是不是 Unity（`libunity.so` + `assets/bundle`）② 抓魔数 ③ 用 `strings libunity.so | grep -i unity` 找自定义魔数 ④ 分块大小试探 ⑤ 解开后交 UnityPy。 |

### 遇到"新游戏打不开"的标准动作

1. `file` / 十六进制看头 16 字节，是不是 `UnityFS`；
2. 不是 → 在 APK 的 `lib/*/libunity.so` 里搜 `UnityFS`、`UnityFS\0`、`UnityWeb` 等串，看附近有没有自定义魔数；
3. 用本仓库 `脚本/火影解包器.py` 当一个"魔数无关"的解析器试：它会按 `flags & 0x3F` 判断压缩类型、
   按块容量截断 LZ4，**只要数据块是标准 LZ4，目录表解不开也能硬解**（本次就是这么绕过去的）；
4. 全解不开再考虑反编译 `libunity.so`。

## 四、还有一个坑：素材到底在 APK 里还是在下载目录里？

**两个地方都要扫，它们是互补的。**

| 位置 | 内容 | 本次数量 |
|---|---|---|
| `base.apk` → `assets/bundle/` | **随安装包走**：图集、Spine 骨架、Lua、大部分 UI | **8,444 个包 / 1.09 GB** |
| `files/999/bundle/` + `files/1.80.80.8/bundle/` | 热更新下载的资源 | 63,157 + 1,048 个包 |

表情的 `EmojiAtlas_1` 图集和 64 个 `common_emojispines_*` **只在 APK 里**。
只扫下载目录 → 会得出"表情图集不存在"的错误结论（本次就栽在这，绕了很久）。

`脚本/00_从APK解包.py` 就是干这个的。
